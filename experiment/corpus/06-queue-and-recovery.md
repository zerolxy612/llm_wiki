# 长任务的进度、取消与恢复

本文是原创实验资料，不代表已经实现全部建议。

任务状态包括 pending、processing、done、failed 和 cancelled。成功导入数应与失败、取消数分开。8 个任务中 3 成功、2 失败、1 取消、2 等待时，成功比例是 3/8；已停止执行的任务数是 6/8，两者含义不同。

用户暂停意味着不启动新任务，取消意味着保留一个可以重新发起的停止状态。取消请求发出后，旧请求可能仍在返回，必须防止旧结果污染新状态。已经写入的共享页面不能为了取消而直接删除。

恢复至少要区分缺少模型配置、服务商限流、可重试网络错误和不可重试错误。自动重试需要有界，重启恢复需要持久化队列。进度 UI 不应编造 token 百分比或没有统计依据的剩余时间。
